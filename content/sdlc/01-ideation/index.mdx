## Purpose

The phase most solo developers skip — and exactly why they freeze when projects get complex.

**Key question:** *"What am I building, for whom, solving what problem?"*

<Callout type="warn" title="Most Common Mistake">
Skipping ideation and jumping straight to code. Without clear requirements, you'll build the wrong thing or freeze when the project grows complex.
</Callout>

## Steps

<Step number={1} title="Define the Problem Statement" status="growing">

Write one sentence: **What problem does this app solve?**

Example: "Freelancers lose track of invoices across email threads and spreadsheets."

Be specific. Vague problems produce vague solutions.

</Step>

<Step number={2} title="Identify Target Users" status="growing">

Who uses it? This affects every decision downstream.

- Yourself → optimize for your workflow
- Specific niche → research their pain points
- General audience → start with a narrower scope

**Ask:** What does this person struggle with today?

</Step>

<Step number={3} title="Apply MoSCoW Prioritization" status="growing">

| Priority | Description | Rule |
|----------|-------------|------|
| Must | Non-negotiable core | Max 3-5 items |
| Should | Important but not critical | V1.1 |
| Could | Nice to have | Maybe someday |
| Won't | Out of scope now | Say no explicitly |

Keep Must to 3-5 items. This is your MVP.

</Step>

<Step number={4} title="Write User Stories" status="seed">

Format: *"As a [role], I want [action], so that [benefit]"*

Examples:
- "As a freelancer, I want to create invoices, so that I can bill clients"
- "As a freelancer, I want to track payment status, so that I know who owes me"

Each story = one testable feature.

</Step>

<Step number={5} title="Define MVP Scope" status="seed">

Only 2-3 core features. Do **NOT** build everything. Solo devs die here.

**Rule:** If you're unsure whether to include something, exclude it. You can always add features later.

</Step>

## Checklist

## Output Documents

| Document | Description |
|----------|-------------|
| PRD | Problem, users, features, MVP scope, success metrics |
| User Stories | "As [role], I want [action], so that [benefit]" |
| MoSCoW List | Feature classification: Must / Should / Could / Won't |

<Callout type="tip" title="Golden Rule">
Don't aim for perfection. Aim to go through every phase at least once. First time will be messy — that's normal.
</Callout>
