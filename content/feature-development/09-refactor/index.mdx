## Purpose

Every feature increases system complexity. Without deliberate maintenance, systems decay over time — slowly at first, then catastrophically.

Good engineers continuously:
- simplify code that grew complex during development
- reduce coupling that crept in under deadline pressure
- improve naming that made sense at the time but is now confusing
- improve test coverage for paths discovered in production
- extract abstractions that appeared naturally during implementation

## The Long-Term Engineering Mindset

Professional engineering optimizes for:

```
Long-term system evolution and maintainability.
```

Not just:

```
Closing tickets and shipping features quickly.
```

## What to Refactor After a Feature Stabilizes

<Step number={1} title="Code Simplification" status="growing">

- Extract repeated logic into well-named shared functions
- Remove dead code paths and commented-out blocks
- Improve variable and function naming for future readability
- Reduce function complexity (aim for functions that do one thing)

Rule: future-you should be able to understand present-you's code in 6 months without any context.

</Step>

<Step number={2} title="Test Quality Improvement" status="growing">

- Add tests for bugs you fixed in production — they were real edge cases
- Improve test descriptions so they read as documentation
- Remove brittle or flaky tests that give false confidence
- Add coverage for edge cases discovered through real usage

</Step>

<Step number={3} title="Architecture Cleanup" status="seed">

- Extract abstractions that appeared naturally during implementation
- Fix coupling issues you discovered while building
- Improve module boundaries that leaked during development
- Update architecture documentation to match current reality

</Step>
